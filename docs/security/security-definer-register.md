# Production SECURITY DEFINER warning register

Audit date: 2026-09-14. Production project: `mcueezodawllcgtloghc`. Source baseline: main `8cb26d0f3c4c0d0398b983c8dd127c1a00eb95d9` (PR #53).

## Decision and limits

All 38 signed-in-executable warnings have an individual rationale below. The accepted directions require legacy retirement and narrower current-student tutor access; organization-authorized date-only metadata is accepted. Current production behavior remains documented until reviewed changes are deployed. This register is an engineering justification, not a signed risk acceptance or a penetration-test certificate. The broader security gate remains OPEN.

Production catalog confirms 47 public SECURITY DEFINER functions in total, 38 executable by authenticated and zero executable by anon. Each of the 38 restricts execution to the owner and authenticated role and has a fixed search path. Neither anon nor authenticated can CREATE in public. The nine remaining definer functions are outside this advisor category. These ACL facts do not alone prove body authorization.

The [Supabase advisory](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable) flags privileged execution exposure. Switching all functions to invoker or revoking authenticated access would break intended RLS predicates, controlled projections or mutators. Review the body and dependent callers before changing privileges.

Exact production definitions were inspected read-only and are not included in this publication. Raw production snapshots were excluded after automatic publication review; this register contains summarized boundary reasoning and repository test references. The test column lists files containing the function name, not a claim that every branch or concurrency path is tested. Missing direct references may have indirect RLS coverage; they remain traceability gaps until mapped to explicit assertions.
